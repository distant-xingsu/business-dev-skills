## 本地使用

例如：`$dev-pc-product-ui-design 调整客户编辑弹窗。保留控件默认尺寸，修正标签对齐和提示出现后的留白。`

将所需的完整技能目录从 `skills/` 复制到本机技能目录（例如 `~/.codex/skills/`），保留目录名及其内部结构。若已安装旧版，请将旧目录移出技能发现路径，避免重复。新标识即原标识加 `dev-` 前缀；旧脚本或提示词中的显式调用也需同步。

## 这些技能体现的开发习惯

- **先定对象和完成条件。** 单页问题只追相关操作链。已有项目先读规则、真实调用方和用户认可的同类页面；先要方案就只交方案，明确实施才改代码。
- **借鉴 CRM 的做法，保留目标项目的习惯。** 紧凑靠减少叠加的内外边距，保留默认控件尺寸；表单按用途定宽，常用按钮选语义一致的 Carbon 图标，颜色随主题。说明按需出现，必要的 Alert 与表单保留间距。
- **按职责拆分。** 页面编排业务，独立弹层管理自己的草稿，公共布局只管布局。派生值不重复存，请求走已有 API 层；优先复用真实能力，不为了结构好看增加包装层。
- **把动作与结果分清。** 普通退出叫“取消”，不提示“取消成功”。选择回填、保存资料、正式提交分别表达。模型生成建议、产生草稿、执行动作也是不同阶段。
- **保护数据边界。** 核对字段、枚举、分页、空值、日期精度与实际数据范围。权限和合法状态由服务端判断；界面隐藏、列表过滤、模拟成功都不能代替真实业务结果。
- **按风险验证并停止。** 样式看受影响界面；保存看提交与回读；权限看相邻允许和拒绝案例；编辑器看实际操作中和结束后的状态。只报本次证据，满足完成条件就结束，不把未发布或未全量复验列成新缺陷。

## 从问题选择技能

| 例子 | 从哪里开始 | 判断完成的依据 |
| --- | --- | --- |
| 搜索栏占了半屏，日期和按钮挤在一起 | PC 产品界面设计 | 同一窗口下控件对齐，查询行为保持原样 |
| 修改条件再翻页，结果混入未提交的条件 | 业务接口联调 | 翻页沿用已提交条件，迟到响应不覆盖新结果 |
| 搜索能找到记录，但详情入口与岗位范围不一致 | 业务权限与流程；若查询截断再结合接口联调 | 合法入口能用，直接访问越界对象被拒绝 |
| 保存过程中继续移动节点，界面却显示全部已保存 | 编辑器状态与操作；若需核对后台版本再结合接口联调 | 只确认提交时的快照，新移动仍标为未保存 |
