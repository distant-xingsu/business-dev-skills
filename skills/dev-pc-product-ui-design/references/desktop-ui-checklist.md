# 验收与反例

## 验收方式

以修改批次为单位，先明确要验证的具体问题，复用仍适用的结果。界面变化缺少适用证据时，记录改造前的可观察问题，再使用同一页面、相同 CSS 视口和相近真实数据对比。现有项目没有可运行环境时报告静态发现及未验项，不把推演写成实测。

通常先用一个代表性桌面视口；只有布局、断点或窗口行为受影响时，增加相关的窄、宽、矮窗口或缩放场景。1280x720、1440x900、1920x1080、3440x1440 及 125%/150% 缩放仅为可选采样，不是每次必跑清单、支持上限或移动端要求。

浏览器应用在浏览器验证，Electron 的窗口/文件/IPC 等行为在 Electron 验证。尊重项目暂停或启动限制，不能为了截图擅自恢复服务。优先已有工具，不自动下载安装运行时。

## 视觉与空间

以下只选与本次改动直接相关的条目：

- Header/菜单两类外壳都能正确分配剩余高度；有 Tabs 时不重复减高度。
- 同排控件实际外框对齐；长标签与日期范围不会顶走搜索/重置。
- 没有重复页标题、空 toolbar 或多层 padding；表格有效空间确有改善。
- 宽屏工作区伸展，表单仍易读；窄窗口表格内部滚动，分页可达。
- 文本层级、颜色语义、表头/斑马纹/hover/选中清晰；涉及主题变量或主题下的呈现变化时补查对应已有主题。
- 浮层有视口上限、稳定操作区；表格或表单的滚动不与页面重复。
- 长文本有完整查看途径；图标按钮有可访问名称，键盘焦点可见。
- 未为装饰新增统计卡片、功能或主题入口。

## 交互与组件

按改动范围覆盖，不增加不相关测试：
- 查询、重置、翻页和页大小切换的请求次数/参数正确；旧响应不会覆盖最新数据。
- 手动查询项目翻页不会意外带入未提交草稿；即时查询项目保留其现有语义。
- loading、空数据、失败、未接接口有区别；异常后操作可恢复。
- 涉及请求生命周期时，覆盖打开 A、切换 B、清空上下文或关闭等相关路径；迟到的成功、失败和 finally 不覆盖当前状态。涉及弹层时，取消不改原记录，成功只刷新一次。
- 涉及详情页签时，核对按需读取、局部失败重试及换对象后的分页/缓存失效；涉及打印等依赖操作时，核对真实子组件的数据准备，父层测试替身不能证明子组件已正确隔离旧响应。
- 保存有验证/loading/防重复提交；未保存输入在失败后保留。
- 涉及文案时，按钮、确认框、进行态和结果表达同一动作；普通退出不提示取消成功，业务取消不与退出混淆，具体口径见 [界面文案与操作反馈](ui-copywriting.md)。
- 相关权限下按钮及操作仍正确；不以客户端过滤替代服务端范围。
- 附件按涉及的上传、错误、重试、预览/下载能力检查。
- 页面负责协调，公共布局无业务请求；抽屉/弹窗独立，简单字段未被过度拆分。
- 独立页面有各自 Vue 入口，目录可识别页面及私有组件；没有用一个万能页面切换多个无关页面，也没有为简单区域强行增加包装文件。
- 页面拆分后既有路由、权限元数据、keep-alive 和返回行为保持正确；跨页复用通过模块公开组件，不引用另一页私有目录。
- 修改公共组件时抽查真实调用方，尤其单表、多表和嵌套布局，避免局部优化全局回归。

按风险选择项目已有检查：文档核对内容、差异及链接；样式/文案核验受影响界面；逻辑选择相关测试或类型检查；权限、持久化和状态流转保留对应业务链证据。构建仅用于构建/资源风险或明确的产物检查，不把命令表串成固定流程。后续仅复验新修改使之失效的部分，满足完成条件即停止；同一验收环境连续两次同类失败且无新证据时，停止相同重试并报告具体阻塞。报告实测载体、视口、状态及限制，区分静态、隔离接口和真实业务链证据。

## 使用技能后的场景推演

下列用于验证技能指导是否遗漏条件；推演通过不代表页面已经运行通过。

1. 既有 Vue 列表，Header 已有页名，接口服务端分页：应复用骨架、避免重复标题、保留 total 与查询语义，不能新增主题或二次分页。
2. 两种外壳已有切换，内部 Tabs 可关闭：应共享 head/menu/main 内容，Tabs 有无都正确分配高度，不能引入两份路由/业务状态。
3. 3440 宽而窗口很矮：表格扩展、筛选字段有合理宽度、分页可达；不能放大字体、锁死 1920 宽或要求手机适配。
4. 编辑流程塞在页面：独立业务弹窗拥有草稿/验证/保存，父页面协调刷新；不能把所有表单放 Pinia 或生成一堆无职责子组件。
5. 参考项目含国际化、只读抽屉、Electron 文件能力：只提炼布局与组件契约，不默认把三项能力移植到普通 Web 项目。
6. 没有截图/运行环境：可以做代码诊断和结构推演，明确视觉待验；不能把代码检查报告为用户满意度或截图验收。
7. 客户列表与客户详情原本混在一个组件：保留各自页面入口，按需共享表单，简单列表内容可留页面；同一详情不同 id 不重复建页。页面内状态筛选 Tabs 不擅自升级成新路由。
8. 只修改某状态标签的颜色：查对应状态及现有语义变量，核验受影响界面；不重构页面、不新增全尺寸检查或完整构建。
9. 多页签详情切换业务对象：当前主体先加载；日志/流程按需加载，空对象失效旧请求，子表页码按上下文重置；不把旧对象信息显示在新对象下。
10. 工时页本地即时筛选、组态画布编辑：保留已有交互与数据契约，不强制改成 CRM 的远程提交式搜索；保存文案对应实际持久化范围。

## 交付

完成条件以本次明确需求和适用检查为准。证据限制不自动变成缺陷或待办；只有指出具体需求缺口才追加验证。隔离验证已覆盖改动且接口、持久化契约未变时，不自动升级为真实数据库、原生全链或全角色验收；需要真实链路证明的变更仍保留对应证据。未纳入任务的发布与部署不作为开发完成门槛，不为非必要证据反复搭建环境。

简短说明改了哪里、解决了什么可见问题、业务不变量是否保持、实际执行了哪些检查。必要时附前后截图。用户明确认可的设计才作为后续基准；未认可的样稿标为候选，不冒称已获认可。
