# 复杂工作区减负

当多个角色、对象或步骤共用一个工作区，先看操作路径。局部样式或文案任务不因此扩成导航重组。

## 先还原用户要完成的事

用一句话写清：谁在什么范围内，对哪个对象做什么，看到什么才知道做成了。沿现有入口走一遍，从选对象、采取行动到确认结果。标出在哪一步找不到入口、看不清状态、被迫切页或看到重复信息。仅从代码推断的问题与实际看到的问题分开。

有多个角色或任务时，分别看职责和使用时机。优先沿用项目已定义的工作区和权限，不把管理端的配置入口镜像到业务端，也不把项目级操作误呈现成全局操作。

## 先减内容，再调空间

| 内容在这一步的作用 | 放置方式 |
| --- | --- |
| 识别当前范围、对象、状态，或完成当前任务 | 留在主区。主要动作靠近它作用的对象，标清保存或提交的范围。 |
| 阻止继续、提示风险或决定下一步 | 放在受影响的位置，解释发生了什么和可做什么；失败、未接通、空数据、已保存与已生效分别表达。 |
| 需要追查，但平时不影响决定 | 默认给能判断的摘要；历史、证据、原始数据、技术参数在相关位置按需展开，沿用已有入口。 |
| 和已有入口指向同一任务，或只重复标题、状态和说明 | 先合并、复用或移除重复表达。若入口承担不同权限、恢复或定位需求，保留并说明差异。 |

选择现有容器中最轻的一种：短详情就地展开；需要对照主区的资料用侧区；独立步骤或真正需要单独定位、分享、恢复的任务才考虑独立页面。深链用于定位当前对象，不必多造一个菜单。不要把低频内容全塞进第二层菜单，也不要把依赖当前决策的信息藏进默认折叠区。

标题、卡片、边框和徽标只有在能表达归属、优先级或状态时才保留。不要用更小的控件、更多标签页、换色或再包一层面板掩盖入口和内容重复。除非本次任务需要，不改主题、组件库或应用外壳。

## 设计决定与验收

说清哪些内容保留、合并、按需显示，以及用户在哪一步受益。不用为审查另建常驻页面或规则文件。例：设备运行工作区把当前设备、异常状态和处置动作放在主区；正常心跳明细在状态旁展开；影响当前处置的异常原因直接显示。配置保存后的回读与设备实际生效分别确认。

有界面改动时，在可比视口走一次原主任务，再验证受影响的例外路径，例如切换对象、恢复深链、找回证据、保存失败或权限受限。核对对象标识、草稿边界、结果反馈和低频入口仍可达；不以区块变少或截图变整齐代替任务验证。
