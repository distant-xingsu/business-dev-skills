# 布局与页面模式

## 应用外壳

外壳只承载导航、Header、路由区和已有 Tabs，不承载页面请求、筛选、弹窗和分页。

```text
菜单通高                    Header 全宽
+----------+-------------+  +------------------------+
| Menu     | Header      |  | Header                 |
|          +-------------+  +----------+-------------+
|          | [Tabs]      |  | Menu     | [Tabs]      |
|          | Page        |  |          | Page        |
+----------+-------------+  +----------+-------------+
```

两个外壳可用相同 head/menu/main 插槽装配，保持业务内容不依赖导航摆放。仅在已有或确认需要切换时提供切换能力；Tabs 在两种外壳里都可以独立存在。

Electron 自定义标题栏额外占用的高度由窗口外壳管理，不在每页减一次；涉及 IPC 的代码留在当前项目适配层。

## 业务骨架

优先寻找当前项目等价组件；下列命名仅用于说明区域组合。

| 工作内容 | 骨架 | 区域职责 |
| --- | --- | --- |
| 单内容、空状态 | B | 一个内容区，按内容选择滚动 |
| 上方操作/摘要、下方详情 | TB | top 自适应，body 伸展，可选 footer |
| 查询列表 | THB | top 查询；head 列表操作；body 表格；footer 分页 |
| 分类树与列表 | LR | 左栏有宽度约束，右栏占剩余空间 |
| 顶部条件、下方左右业务 | TB + LR | 外层关闭内容滚动，左右面板各自管理 |
| 多子表详情 | TB + 分组内容 | 长详情滚动；子表分页按业务独立 |
| 高频逐条处理 | 列表 + 详情 | 保留列表上下文，详情请求有独立生命周期 |

如果分页组件已包裹表格并预留底栏，就放入 body，不再生成第二个 footer。空 slot 不产生空白标题行。已有 Layout 可组合时不新增近似组件。

同时核对权限过滤后的实际内容：操作全部隐藏时不留下空工具栏或重复间距。由现有布局处理空区收缩，不复制参考项目的 CSS 选择器去推测业务权限。

详情容器按任务选：短只读详情适合抽屉；多子表、多流程且需独立地址的内容适合详情页；表单适合独立编辑弹窗或项目允许的编辑抽屉。某些项目限制抽屉只读，须遵守，但不能推广到所有项目。

## 高度、宽度与滚动契约

- 外壳拥有可用窗口高度，页面继承；不要在每层设置 100vh 或复制 calc(100vh - 常数)。
- 可伸缩中间层设置 min-width: 0、min-height: 0；固定工具区和分页不得被 flex 压缩。
- 筛选区高度随换行变化，不靠固定 50px 裁掉控件。过多字段按已有高级筛选方式折叠，不擅自隐藏核心条件。
- 表格 height="100%" 只有在祖先高度链完整时才有效；分配剩余高度后再由表格管理滚动。
- 普通长详情或表单沿用项目滚动组件；Element 项目优先 el-scrollbar。表格已有内部滚动时关闭外层同轴滚动，其他组件库不引入 Element 依赖。
- 左右工作区允许独立滚动，但每个面板明确唯一滚动容器；父容器不同时纵向滚动。
- 公共骨架负责区域间距、表面背景和统一内边距，页面只负责业务内容排布。检查 padding 是否由布局、分页包装、业务 div 重复叠加。

缺少骨架时可按以下结构思考，在当前组件体系内实现；这是布局示意，不是要求新建同名框架：

```css
.page {
  height: 100%;
  min-width: 0;
  min-height: 0;
  display: flex;
  flex-direction: column;
}
.filters, .toolbar, .pagination { flex: 0 0 auto; }
.table-region {
  flex: 1 1 0;
  min-width: 0;
  min-height: 0;
  overflow: hidden;
}
```

overflow: hidden 用于分配边界，不用于掩盖被截断的字段；表格组件本身必须获得滚动及完整访问能力。

## 宽屏策略

依据 CSS 窗口尺寸，区分物理像素与缩放后的可用宽度。1280、1440、1920、2560、3440 都只是采样，不是固定断点清单或上限。

表格工作区撑开，字段列设置合理最小宽度，操作列宽度有边界。增加屏幕宽度不应拉大所有字号和行距。表单字段按可读性限制宽度，整页不居中缩成孤岛；必要时用业务分组利用横向空间，不凭空添加信息面板。

窄桌面先让筛选换行和非关键工具收纳，表格按实际列数内部横向滚动。分页可换行但不得遮挡或超出窗口。弹窗、抽屉都有最大视口宽高限制，内部长内容滚动，footer 可达。

## 后台数据列表的完整操作链

假设已确认任务是客户查询、查看详情和编辑；下列字段只做设计推演，不是授权新增业务或生成 mock 数据。

```text
应用 Header / 菜单 / 已有 Tabs
+-----------------------------------------------------------+
| 客户名称 [          ] 状态 [      ]  [搜索] [重置]        |
+-----------------------------------------------------------+
| [新增客户]                         已有的列表级操作        |
|-----------------------------------------------------------|
| 客户名称        联系方式       状态      更新日期    操作  |
| ...                                                       |
|                          表格剩余高度                     |
|-----------------------------------------------------------|
| 共 N 条                        每页条数  上页 页码 下页    |
+-----------------------------------------------------------+
```

实际执行前确认新增是否属于已有业务；没有则不画该按钮。首列有真实详情入口才用链接样式；编辑保留独立语义。若项目在 Header 已显示页名，主体不再加大标题。

组件树优先为“页面 -> 现有布局 -> 现有搜索/表格分页 + 独立编辑弹窗”。只有查询逻辑或列业务确实复杂，才继续拆 Filters/Table；短表格可以留在页面。

对同一案例做尺寸推演：窄窗口搜索换行但按钮可达；宽屏表格扩展，搜索字段不等分撑满；矮窗口保住分页并让表格滚动；打开编辑后保持列表条件与页码。

布局应服务已存在的操作链，而不只是首屏截图。按本次涉及的环节安排内容与反馈：

| 环节 | 界面与状态配合 | 用户获得的好处 |
| --- | --- | --- |
| 找到记录 | 查询区表达当前条件；提交式查询的翻页沿用已提交条件 | 明确当前结果为何出现，输入草稿不影响翻页 |
| 查看详情 | 根据内容量选择现有详情页或抽屉；保留列表返回上下文 | 查看后能继续处理原来的记录位置 |
| 编辑记录 | 独立业务弹层管理草稿，操作区稳定可达 | 取消不污染原记录，错误后可继续修改 |
| 保存成功 | 由一个所有者刷新受影响区域，沿用现有页码和返回约定 | 不整页闪烁、不重复请求、不无故跳回首页 |
| 请求失败 | 错误与重试留在所属区域；相关操作按状态恢复 | 能判断失败位置，不用重新开始整个流程 |

这些是已有能力之间的配合要求，不意味着新增详情、编辑或缓存功能。返回恢复优先复用既有路由、keep-alive 或页面状态；没有恢复机制时只在本次业务确有需要且获得授权后补充，不为每页增加持久缓存。

## 多区块详情的阅读顺序

详情上方先交代业务对象、当前状态和已有关键动作；主体按业务关系组织基础资料、明细与相关记录，历史与日志放在后续区域或已有页签。只呈现真实字段，不为了套布局补统计卡片。

识别信息保持稳定，变长内容在所属区域滚动。只读文字和可编辑控件保持标签与分组关系；错误重试靠近失败区域。子表按各自数据规模与接口分页，流程按查看需要读取；具体生命周期见 [Vue 组件契约](vue-component-contracts.md)。

只有项目已有独立查看或处理入口时才做跳转；共享详情沿用稳定业务 ID 与来源上下文，不用显示名称拼路由或猜权限。
