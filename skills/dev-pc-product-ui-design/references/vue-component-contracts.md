# Vue 组件契约

## 先复用，再按职责拆分

查公共组件实现和至少一个真实调用方，确认 slot、prop、事件、默认滚动和高度。不要根据 LayoutTHB、TableGroup 等名称推断能力：表格“Group”可能只封装操作列，分页组件可能同时拥有表格容器。

公共布局只接收内容和布局配置，不调用业务 API、不读业务权限、不维护筛选。跨模块复用走公开接口，不能引用其他业务模块内部实现。

接入既有能力时，先核对下列最小契约；只核对本次实际使用的组件：

| 公共能力 | 需要确认的契约 | 页面保留的责任 |
| --- | --- | --- |
| 布局 | 实际 slot 名称、高度链、内边距和滚动所有者 | 业务内容与区域组合 |
| 搜索 | 字段配置/插槽、值绑定、提交/重置事件、已有偏好隔离 | 字段含义、默认条件与查询用例 |
| 表格分页 | 是否包裹表格、页码起点、total、页大小事件与自动纠页 | 对齐接口分页、协调唯一请求入口 |
| 空状态/错误态 | loading、空结果、失败、重试各由谁展示 | 根据真实请求结果选择状态 |
| 业务弹层 | 打开参数、关闭规则、成功事件及返回内容 | 选择业务对象、协调成功后的刷新 |

同名组件也可能有不同能力；移植的是职责分工，不是参考项目的 import 路径或 props 名称。发现公共组件已承担某项职责时，删除本次新增的重复处理，不通过第二层包装补一套同名行为。

| 层级 | 状态/职责 | 与外界协作 |
| --- | --- | --- |
| 页面 | 查询用例、分页、选中标识、打开编辑与刷新协调 | 调用业务 API 或已有 composable |
| 搜索业务区 | 条件编辑与展示 | 类型化 model，search/reset 意图 |
| 表格业务区 | 列、单元格与选中/行操作呈现 | rows/loading 输入，selection/edit 等事件 |
| 独立弹窗/抽屉 | 当前记录草稿、验证、读取和提交状态 | 沿用项目打开接口，成功发 saved/既有事件 |
| composable | 确实可复用的请求或状态生命周期 | 显式参数与返回，派生值 computed |
| Pinia | 跨页共享或已确认的保留状态 | 缓存键、更新/失效/清理约定 |

这是职责划分，不是要求每个页面生成全部文件。简单筛选和表格可留页面；独立业务弹窗、抽屉必须独立 Vue。复杂表单或有独立生命周期的区域再拆子组件。框架通用确认框直接复用，不新建包装器。

目录按业务能力组织，并与菜单功能对应；沿用当前 modules、viewModule 等约定，不为符合某种目录图重排全库。私有组件留业务模块，真正重复的结构才提升公共。

## 页面入口与目录

每个独立业务页面有可定位的 Vue 入口。列表、详情、独立新建/编辑页各自有页面文件；不让一个万能页面通过 route.name、mode 或大段 v-if 承载互不相同的页面。页面内的筛选 Tabs、展示切换或同一流程的步骤不自动算独立页面，不为本规则额外创建路由。

相同页面的不同记录 id、路由别名可以复用同一入口；同一表单的新建/编辑若项目本来共用流程，可以复用表单。需要两个独立页面时分别保留入口，在内部共享真正相同的内容，不复制整份表单。

新建结构或当前目录混乱时，优先采用“业务模块 -> 页面目录 -> 页面入口 + 页面私有 components”。示例只展示职责位置，不要求创建全部文件：

```text
customer/
  pages/
    customerList/
      index.vue                  # 简单搜索、表格、分页可直接写这里
      components/
        CustomerEditDialog.vue   # 列表专属业务弹窗
    customerDetail/
      index.vue                  # 独立详情页面
      components/
        FollowUpSection.vue      # 仅当跟进区确实复杂才拆
  components/
    CustomerForm.vue             # 确有多个页面复用时才放模块级
```

已有清晰的 viewModule/customer/list.vue、detail.vue 等组织也可保留；关键是目录和命名能识别页面所有权，不为套目录图迁移全库。index.vue 与具名 Page.vue 沿用项目习惯，不同时维护两份入口。

页面专属组件不堆到全局 components，也不由另一个页面直接引用其私有 components。多个页面确实共用时再提升到模块公开组件；跨模块复用再评估公共层。页面目录只在有内容时创建 components/composables，不预建空目录。

## 拆分判断

页面不是只能装配组件的空壳：常规筛选字段、短表格列、简单摘要和局部事件可直接写在页面，继续复用公共 UI 控件与布局。除独立业务弹窗/抽屉外，提取组件应能说清至少一个实际理由：

- 存在明确、稳定的重复使用需求。
- 区块具有独立业务职责和状态生命周期，拆开后更容易理解和验证。
- 复杂模板/交互已经妨碍阅读页面主流程，拆分后输入和输出仍清楚。

不按固定行数强制拆分，不因“搜索/表格/按钮是一个区域”就新建包装组件。只转发大量 props/events、深层透传或为了一个按钮产生文件，通常说明边界过碎，应让内容回到合理的页面或业务区块。

实现前的组件树只列实际需要的文件，简述拆分理由。页面分离时保留既有路由路径、名称、权限元数据、组件名/keep-alive 约定及返回行为，不能只搬模板而丢失导航和缓存语义。

## 查询与分页

区分查询草稿与已应用条件，但先读取项目交互：手动提交、Enter、即时筛选或防抖均可能合理。优化外观不得把一种偷偷改成另一种。手动提交项目输入只改草稿，查询才更新已应用条件，翻页使用已应用条件。

无既定约定的新远程业务列表优先“查询 + 重置”，适合多条件集中提交；已加载完整数据的本地筛选、日历导航或业务上下文切换按用例保留即时反馈。依赖字段和候选项加载不应顺带提交主列表。Enter 提交须避开中文输入法组词确认、多行文本和下拉自身的选择行为。

复用搜索组件要接入真实字段、值和事件契约，不能只套视觉外壳。项目已有常用筛选/偏好保存时，沿用账号与场景隔离及恢复规则；没有此能力时不因套用页面模式自动新增。公共组件应统一负责已提供的条件收纳、间距和交互，页面不再复制一套。

查询和重置的页码规则依据当前项目与接口。一次用户动作只触发一次有效请求，避免 page watch 和点击回调重复请求；旧请求不可覆盖新结果，使用既有取消机制或请求序号。

列表 loading 不应无故锁住整个外壳；连续提交有保护，失败恢复操作。重置恢复项目默认条件，不总是把所有字段置空。默认部门、日期和数据范围不能被清掉。

服务端分页使用响应的真实 total，不二次切片；完整数组本地分页只在接口明确返回完整范围时使用。改变页大小通常回第一页，但保留项目约定。修正失效页码应发生在有效响应后，不能把 loading 时的临时 total=0 当作真实空列表导致来回跳页。

Element 列表按项目视觉约定使用 stripe、border；需要填充剩余高度且祖先高度链完整时再用 height="100%"。使用既有空状态与操作列。左右分页左侧总数/摘要，右侧分页控制；已有包装负责间距，页面不叠加同类样式。详情中的子表同样遵守真实分页契约，不因放在页签中就固定取前若干条而遗漏后续入口。

## 详情页与请求生命周期

先读取主体，再按当前页签或实际操作读取流程、日志等非首屏数据；业务明确需要预取时保留。每个区域管理自己的 loading、error 和重试，同一对象已加载或正在读取的数据按现有机制复用，不因此引入跨页面持久缓存。

以稳定业务 ID 和请求代次识别当前上下文。切换对象、上下文清空、关闭或卸载时，使相关旧请求失效；成功、catch、finally 写状态前都确认仍属当前上下文。空 ID 不请求；对象变化时清理旧详情，并按该子表契约重置页码和已加载状态。保留项目既有 keep-alive 激活与返回刷新约定。

打印、导出或后续操作若依赖尚未读取的数据，应等待当前对象数据就绪，失败可重试；异步准备期间换对象则取消旧操作。子组件有自己的请求时也须核对其写入边界，不能只保护父组件。只在本次涉及这些能力时核验，不自动扩成全系统性能改造。

## 弹窗、抽屉和表单

一个业务弹窗负责一个清晰任务。沿用已有 props/emits/v-model 或 defineExpose 打开方式，不并行维护两套开关状态。子组件不直接修改父级表格记录：打开时生成独立草稿，取消不得污染列表。

示意契约，名字需映射到项目实际接口：

```ts
interface EditInput { id: string }
interface SavedResult { id: string }
// 页面选择 id；弹窗加载并编辑草稿；保存成功 emits('saved', result)。
// 只有一个所有者刷新列表，避免弹窗和页面各查询一次。
```

每次打开生成当前会话草稿并清理必要验证；请求失效遵循前述生命周期规则，特别避免旧保存结果关闭新会话。未保存退出行为沿用产品规则。

表单标签位置、宽度、后缀和分列优先沿用项目已认可的同类表单。没有基准时再按内容选择自动宽度、统一宽度或顶部标签；Element 的 label-width="auto"、label-suffix 和 el-row/el-col 只是可选实现，最终以实际标签与控件对齐为准。@submit.stop 只停止传播，不阻止浏览器默认提交；需要阻止默认行为时按业务使用 .prevent。

涉及弹层或键盘交互时，沿用组件已有焦点管理：打开后落到适合当前任务的字段或内容区域，不默认聚焦危险动作；校验失败定位首个可操作错误，关闭后返回仍存在的触发入口或合理相邻位置。异步加载、字段禁用或入口消失时，不强制聚焦不存在的节点。

Enter、Esc 与 Tab 遵循项目及组件约定。提交不得抢占输入法组词、多行输入或下拉选择；Esc、遮罩及关闭按钮共用既有未保存退出保护，不能绕过保护丢失输入。模态弹层的焦点不意外落到背景操作，嵌套弹层按当前层处理。优先复用组件机制，不另加全局键盘监听；仅在本次涉及的路径核验。

保存校验通过后进入提交态，按钮 loading 并防重复提交；finally 只恢复当前会话状态，失败保留输入，成功才通知父级。日期精度、空值、枚举和服务端错误按接口处理，不用 UI 重排改变提交含义。

长表单沿用项目滚动组件，Element 项目优先 el-scrollbar，操作区始终可达。弹窗与抽屉宽度有视口上限，不能照抄参考里的固定 850px。详情多子表/流程时评估独立详情页；项目只读抽屉规则仅在该项目生效。

保存文案明确作用对象与范围：本地草稿、单个资源后台保存、整个工作区提交分别表达；独立资源库操作与画布撤销/保存分开。对于提交超时等结果不确定的情况，沿用项目已有幂等或回读核对机制，不盲目再次创建，不显示假成功。编辑器已有的未保存提示、撤销重做与批量操作事务边界须保留，不把普通表单的保存方式强套到画布。

## 附件与消息

复用上传、文件列表、预览、下载和消息封装。附件组件可封装必要上传适配，但业务页面不重新拼鉴权头和上传地址。

区分未上传、上传中、失败、空文件、解析失败、上传成功但未关联业务。删除文件与解绑关联不是同一操作。查看/下载/删除遵循真实能力，Element 本地 file-list 不能当服务端成功凭证。

消息由现有请求层/用例层统一承担，避免失败被重复 toast；字段错误尽量靠近字段，失败不显示成功反馈。WebSocket 只有实时通知业务需要且已确认才启用，优先现有通道，明确订阅清理、重连和去重，不每页新建连接。

按钮、标题和结果提示按实际动作统一，具体词语及“普通退出 / 业务取消”边界见 [界面文案与操作反馈](ui-copywriting.md)。

## 缓存与样式

缓存先明确保留查询、列表数据还是编辑草稿，按用户和业务范围划分键；切换权限/租户、退出、保存/删除后按需要失效。keep-alive 与 Pinia 缓存分别判断，不默认持久化所有业务记录。

样式分为语义变量、框架映射/覆盖、公共布局、业务局部样式。变量先于覆盖加载；Teleport 的弹层要能继承根级变量。页面 scoped 样式只控制本页，避免 broad :deep、!important 或全局 .el-* 修补局部布局。

参考代码中的 any、桌面存储、权限码和装饰依赖不复制成新项目默认。新接口用明确类型，边界未知值先收窄。
