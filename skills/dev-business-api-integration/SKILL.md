# 业务接口联调

覆盖后台管理系统中从查询、查看、编辑到保存、刷新和重新读取的数据链。处理字段与分页契约、请求触发与响应归属、搜索完整性、保存反馈和幂等核对，不绑定具体前端框架或服务端语言。

## 职责与配合

聚焦真实接口契约和数据状态；界面布局与文案呈现沿用项目规范。权限规则不清时先厘清业务权限与流程，编辑器历史与快照变化按编辑器状态与操作处理。相邻能力只在本次确有涉及时展开，不默认加载其他技能。

## 工作方式

现场接口暂时不可达时，可用脱敏样例验证字段映射和时序，继续独立可做的开发；标明样例来源和验证边界。不要把样例放进默认业务页，也不要用历史回放证明当前接口连通。

先识别当前项目的业务 API、请求封装与响应结构。表单草稿、保存成功、流程提交和异步任务完成分别对应实际结果；任务已受理或进度更新不等于全部执行成功。

1. 明确本次用例、目标环境、触发动作、期望和实际结果。读取调用页面、业务 API、请求层及可用的服务端实现或接口文档，先复现具体问题，不先扫全库。
2. 对齐相关字段：参数与响应类型、必填/可选、空值、枚举、ID、页码起点与 total、日期/时区/精度、错误返回。文档和实现不一致时说明证据，不猜字段；金额计算、授权和数据范围仍由服务端负责。
3. 按实际动作梳理“触发 → 请求 → 状态写入 → 反馈 → 刷新/回读”的所有者。沿用项目请求层、取消机制及公共分页，避免页面和组件同时承担同一刷新。
4. 在已明确的业务规则和授权范围内修复；缺少真实接口时保留明确的未接/失败状态。隔离测试数据不能进入业务默认流程。
5. 按本批变化选择必要证据，完成后报告接口契约、实际核验链路及未验边界。模拟接口通过不能证明后台已接通，历史结果仅在仍适用时复用。

## 查询与响应归属

- 先区分查询草稿和已提交条件。提交式列表翻页使用已提交条件；已有本地即时筛选、日历导航和业务上下文切换保持原语义。候选项加载不顺带查询主列表。
- 一个业务动作只有一个主查询入口；核对 watcher、分页事件、mounted/activated 和显式回调的重叠。不同用途的依赖请求不机械合并。
- 响应写入前核对稳定业务 ID、请求代次和组件/会话是否仍有效。迟到的成功、失败和 finally 都不能污染当前状态；清空上下文、换对象、关闭或卸载时失效相关旧请求。
- 保留服务端分页与真实 total，不在前端二次切片或过滤冒充服务端数据范围。loading/失败时不把临时 total=0 当成确定的空结果触发反复纠页。
- 详情先加载主体；非首屏子页签按业务需要读取，局部错误可重试。同一对象的已读/在途数据沿用现有复用机制，不额外引入跨页持久缓存。

## 搜索结果完整性

仅在查询逻辑、全局搜索或相关范围变更时检查，不把普通页面联调扩展为全库查询审计。

- 核对实际执行顺序：可见数据范围与业务条件应在分页或候选截断前生效。先取固定数量再过滤可能漏掉后续合法记录；优先将条件落实在服务端查询，受契约限制时明确结果上限与补取策略，不无限补取。
- 聚合搜索分别核对各业务分类的范围语义。“本人、下属、部门”等条件不能只改界面标签，也不能把一个分类的授权规则直接套给其他分类。
- 区分当前返回条数、全部匹配数和每类上限；没有真实总数或 hasMore 时，不用返回长度推定全部命中。结果截断应明确表达，需要继续查询时沿用合法列表入口与已提交条件。
- 关联查询的候选上限、去重与排序可能改变最终结果；只针对本次链路判断漏查风险。验证可使用包含“上限之后仍有合法命中”的隔离数据，不以少量正常结果证明无截断问题。

## 保存、回读与不确定结果

- 表单使用独立草稿；校验、提交锁和关闭保护属于同一会话。成功后由一个所有者协调列表或详情刷新，失败保留输入。
- 区分本地草稿、后台资源保存、正式流程提交；提示必须对应实际作用范围。保存已成功而刷新失败要分开表达，不诱导用户再次提交。
- 明确业务拒绝、连接失败与请求结果未知。超时不等于服务端未写入；已有请求 ID、幂等键、版本号或核对接口时按契约使用，不用时间戳生成新键盲目重试。
- 没有可靠核对能力时说明结果未确认，不能用任意同名记录认定本次保存成功。回读核对稳定 ID、关键字段、版本或约定的业务唯一标识。
- 涉及持久化且已具备相应环境和授权时，核对提交 payload 与重新打开后的后台响应。真实写入测试须先明确对象、影响和恢复方式并取得相应确认；缺少权限时继续可独立完成的静态或隔离验证。

## 按风险验证

反馈由一个所有者协调，区分短消息与持续状态：成功后清理已失效错误，关闭或切换对象后旧请求不能弹消息。开发中未接接口在所属区域真实表达，不为每个子请求常驻一条 Alert；正在阻塞操作、结果未知等必要状态仍应可见，布局与间距按界面规范处理。

只覆盖本次受影响路径，例如草稿后翻页、A/B 响应倒序、清空上下文、保存失败后重试或保存重开。只改字段映射时不自动跑全部场景。优先现有定向测试与代表性真实载体，不重复执行被其他命令覆盖的检查。

实际接口、数据库、账号权限不可访问时写清未验项，不修改生产配置、安装工具或伪造成功绕过。数据库、运行配置及发布操作另按明确授权执行。必要检查通过后结束；同一环境连续两次同类失败且无新证据时停止相同重试。

## 场景判断

完成条件以明确需求和适用检查为准，未验边界不自动成为缺陷或待办。隔离测试已覆盖本次变化且接口、持久化契约未变时，不自动追加真实数据库或全角色验收；实际联调、持久化契约变化仍需对应链路证据。未纳入任务的发布不作为完成门槛，不为非必要证据反复搭建环境。

- 查客户第 2 页时新输入了未提交的名称：沿用已提交条件，不能把新草稿带入翻页。
- 保存超时后页面仍可编辑：先判定结果是否可核对，不能直接再次创建或提示已失败。
- 页面已保存但刷新列表报错：保留保存成功事实，提供已有刷新路径，不再次保存。
- 只有模拟请求证据：报告隔离验证通过及真实后台未验，不称全链已接通。
