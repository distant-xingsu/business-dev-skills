# 编辑器状态与操作

目标是让用户能连续编辑、撤销、保存和恢复，并理解当前操作作用于什么对象。优先沿用项目已有 schema、历史管理和渲染机制，不从某一个组态项目推导通用引擎。

## 职责与配合

本技能负责编辑文档、选择状态、历史、快照与渲染之间的协作。面板视觉和按钮文案由 PC 产品界面设计处理；网络保存、幂等及后台回读按业务接口联调处理。只有实际涉及的边界才展开，不自动重构其他编辑域。

## 工作方式

1. 明确目标编辑域、对象、模式和可复现操作，区分布局问题、交互问题、文档状态问题与渲染问题。
2. 找出当前唯一数据源：业务文档、选择集合、视口、临时交互、历史记录、持久化版本及渲染实例分别由谁拥有。按当前实现画最小数据流，不另建重复 store。
3. 确定一次操作的开始、预览、提交、取消及历史边界；核对对象 ID、关联引用、锁定/只读规则和多选混合值。
4. 在已授权范围内修改，保留现有快捷键、坐标系、吸附和选择习惯。只有本次明确涉及才改变数据 schema 或渲染架构。
5. 按变化选择代表性操作核验，报告文档状态、可见结果、历史与保存各自的证据；不把截图正常当作可恢复或持久化正确。

## 状态所有权

- 文档存声明式业务配置；选择、悬停、拖拽中间值、视口及编辑模式依现有边界管理，不混入最终业务数据。
- 属性面板写配置，渲染层消费稳定 schema；页面不跨域直接修改其他编辑器内部状态或渲染实例。
- 派生数据使用 computed 或纯函数，避免节点、面板和 store 各维护一份待同步真相。跨域复用先定义公开契约。
- 对象切换和模式切换时清理临时交互，防止旧面板输入改到新对象。多选混合值明确表达，不能把未修改字段覆盖为默认值。

## 操作与历史边界

- 拖拽等连续操作沿用项目既有“开始快照 → 中间预览 → 结束提交”方式；避免每个 pointermove 都生成历史，取消应恢复本次临时变化。
- 批量修改按当前操作语义形成可理解的历史单元。只改目标对象和明确字段，保留 ID 与关联关系；预检、部分失败或全回滚遵循现有事务约定，不假定批量天然原子。
- 撤销/重做恢复业务状态及必要引用，避免快照共享可变对象。新增操作后的 redo 分支、历史容量和 dirty 标识沿用当前机制。
- 快捷键仅在对应编辑上下文生效；文本输入、弹层编辑和画布操作避免抢占同一按键。新增快捷键或批量能力需要当前任务明确包含。

## 保存、预览与恢复

- 明确保存范围：当前资源、整个文档或独立资源库。保存模板与将模板布置到画布可以是不同事务，不把独立后台操作错误纳入画布撤销。
- 区分内存草稿、本地恢复副本和后台版本，提示对应真实层级；不因存在本地缓存就提示已保存后台。
- 保存使用一致快照。若保存过程中继续编辑，返回成功只能确认已提交的版本，不能清除后续修改的 dirty 状态。
- 预览读取约定的文档/快照，不依赖未同步的面板临时状态。不同编辑模式使用同一数据契约时检查转换与回退，未知字段按版本契约保留或显式拒绝。
- 恢复先核对资源身份与版本，避免用旧草稿静默覆盖新后台数据；冲突处理沿用产品规则，不自动选择覆盖。

## 新组件与素材接入

新增编辑器组件或素材类别时，沿当前扩展机制梳理本次必要链路：分类与缩略图、稳定类型标识、创建工厂或注册表、默认配置、属性面板、序列化和预览。只接入实际需要的环节，不为简单图片替换重构 schema。

- 类型标识与显示名称分开，不能因改名或调整分类顺序改变历史文档的类型含义；沿用既有默认值与版本兼容策略，不强制重写旧文档。
- 编辑视图与预览消费同一业务配置。图片变体、比例、透明度和默认选项按素材及项目契约处理，不复制相邻组件的业务专用字段作为新类别默认值。
- 克隆或模板实例化仅在本次涉及时核对：生成新对象 ID，并重映射内部引用，保留合法外部资源引用。不要全局替换字符串或复用原对象的可变配置。
- 按变更选择验证：纯资源复制核对原图与引用；新增可序列化类型核对创建、保存结构和重新载入；改变渲染或切换行为再核对对应可见状态。构建不能代替交互结果，不因新增素材回归全部编辑器能力。

## 尺寸、拖拽与预览一致性

只在本次涉及文字尺寸、拖拽或预览偏差时展开。先区分业务尺寸、测量后的内容尺寸、渲染变换和选中框范围；明确每项由谁计算，避免面板、画布和预览各维护一套推测值。

- 固定尺寸与内容自适应有明确契约。文字测量使用实际字体、行高、内边距和全部相关行；换行后更新高度与后续内容位置，不靠缩小字体或裁剪隐藏错误。
- 编辑与预览采用一致的布局语义，能复用计算结果时沿用已有公共边界；不同渲染载体核对字体、换行与缩放差异，不因同一 schema 就认定呈现一致。
- 拖动时明确移动的是对象组还是子节点，核对内容、背景、命中区域和选中框同步。尺寸调整后更新相关边界；检查拖动过程中与结束后，不只在结束时刷新外框。
- 返工使用用户指出的同一模板与内容复现，沿尺寸、事件和渲染链追查前次遗漏；只覆盖受影响模式，不把一个参数卡通过扩大为全部模板通过。

面板、表单与提示的视觉可借鉴 CRM；画布坐标、拖拽、历史与预览仍服从当前编辑器模型，不复制 CRM 页面操作替代编辑器交互。

## 生命周期与性能

pointer/mouse/resize 监听、定时器、动画帧和渲染资源按所属生命周期创建与释放。卸载、切换和模式变化仅清理自己拥有的资源，共享纹理或实例不能误释放。

高频状态沿用已有浅响应、批处理或渲染调度；先用可观察证据定位卡顿，再调整相关链路。不因节点多就换引擎、引入 worker 或升级依赖。

## 按风险验证

历史变更核对相关操作的撤销与重做；持久化变更核对提交快照、保存后继续编辑、授权环境下的重新打开；交互变更核对相关选择/拖拽/键盘路径；资源变更核对重复进入和释放。未涉及的能力不自动回归。

浏览器或桌面载体按项目要求选择，通常先用一个代表性视口。真实后台不可用时区分本地快照、隔离接口与真实回读证据；必要检查通过后停止，同类验收环境故障两次无新证据时停止重复尝试。

## 场景判断

完成条件以本次编辑能力及适用检查为准。缺少全场景或真实后台证据只限制结论，不自动增加待办；隔离测试覆盖当前变化且持久化契约未变时，不追加真实数据库或完整编辑器验收。涉及恢复或持久化契约变化仍需对应证据，不为非必要验证反复搭建环境。

- 拖动 100 个对象后撤销一次：是否恢复本次批量移动，取决于既有操作单元，不能误撤销更早编辑。
- 点击保存后又移动节点：保存响应到达不能把新移动标为已保存。
- 独立模板库保存成功后取消画布编辑：按各自事务范围处理，不能暗示模板也已撤回。
- 只调整属性面板间距：使用界面设计指导，不启动历史、保存和渲染机制重构。
